# 대한항공 마일리지 좌석 캘린더 조회 - 설계

## 배경 / 목적

대한항공 마일리지(보너스) 항공권 좌석 현황을 왕복 기준으로 빠르게 조회하기 위한 개인용 웹 툴. 실제 예약/결제는 대한항공 사이트에서 직접 진행하며, 이 앱은 "어디를 언제 갈 수 있고 등급별로 몇 석 남았는지"를 확인하는 용도에 한정한다.

## 범위

- 국내 출발공항(대한항공 취항 국내공항 전체) + 출발월 선택 → 해당 조건에서 갈 수 있는 국제선 노선 목록 표시
- 노선 선택 → 해당 월의 "좌석이 있는 날짜만" 캘린더로 표시, 날짜별/편별로 이코노미·비즈니스·일등석 잔여석 표시
- 가는 편 선택 → 동일한 방식으로 돌아오는 편 조회
- 오는 편 선택 → 왕복 요약 화면 표시하고 종료 (예약/결제 기능 없음)
- 승객 수 입력 없음 — 등급별 잔여석 숫자를 그대로 보여주는 것으로 충분
- 단일 사용자(개인) 전제. 앱 자체 로그인 없음. 백엔드가 `.env`에 저장된 사용자의 SKYPASS 계정으로 대한항공에 내부 로그인해서 조회

## 아키텍처

Next.js 프론트 + 별도 FastAPI 스크래퍼 서버로 분리한다 (B안).

```
[Next.js 15 / React 19 프론트]  --HTTP-->  [FastAPI 서버 (Playwright)]  --Playwright-->  [koreanair.com]
```

- 프론트: 기존 스택(Next.js 15, React 19, Tailwind, shadcn/ui, Zustand, React Hook Form + Zod) 그대로 사용. 화면 간 선택 상태(출발지/월/노선/가는편/오는편)는 Zustand 스토어로 관리
- 백엔드: FastAPI, 레이어드 아키텍처
  - `Router` (controller): HTTP 엔드포인트, Pydantic으로 입출력 검증
  - `AwardSearchService`: 비즈니스 로직 — 좌석 0인 날짜/편 필터링, 등급 매핑, 실패 시 1회 재시도
  - `KoreanAirClient`: Playwright로 대한항공 로그인 및 조회를 수행하는 외부 연동 레이어. 로그인 세션(쿠키)을 캐싱해 TTL(15분) 동안 재사용, 매 요청마다 재로그인하지 않음
- DB 없음 (조회 결과를 영구 저장할 필요 없음, 매 요청 실시간 조회)

## 화면 흐름

1. **출발지 선택**: 국내공항 드롭다운 + 출발월 피커 → [조회]
2. **노선 목록**: 선택한 공항/월 기준 취항 가능 목적지 리스트. 정적 노선맵 데이터로 필터링 (라이브 스크랩 아님, 즉시 응답)
3. **가는편 캘린더**: 목적지 선택 시 해당 월 중 "좌석 있는 날짜만" 표시. 날짜 클릭 시 그날의 편 목록(편명/출발-도착시간/등급별 잔여석) 표시. 여기서부터 라이브 스크랩 (수 초~수십 초 소요, 로딩 스피너 필수)
4. **가는편 선택** → 도착지가 출발지로 고정된 상태로 리턴 월 선택 화면으로 전환
5. **오는편 캘린더**: 3번과 동일한 방식
6. **오는편 선택** → 최종 요약 화면: 가는편+오는편 각각 편명/날짜/시간/등급별 잔여석 표시. 여기서 종료 (예약 기능 없음)

## API 계약

```
GET  /api/routes?dep={공항코드}&month={YYYY-MM}
  → [{ dest: "NRT", destName: "도쿄(나리타)" }, ...]
  # 정적 노선맵 필터링, 크롤링 없음, 즉시 응답

POST /api/calendar
  body: { dep, dest, month }
  → [
      { date, flights: [
          { flightNo, depTime, arrTime,
            seats: { economy: n, business: n, first: n } }
      ]}
    ]
  # 좌석이 하나도 없는 날짜/편은 응답에서 제외 (프론트는 필터링 없이 받은 대로 렌더링)
  # 실제 대한항공 로그인 + 스크랩 수행하는 라이브 엔드포인트
```

## 에러 처리

- 로그인 실패(자격증명 오류, 대한항공 정책 변경): `502` + "대한항공 로그인 실패" 메시지를 프론트에 그대로 전달
- 스크랩 중 타임아웃 / 사이트 구조 변경으로 파싱 실패: `502` + "조회 실패, 다시 시도해주세요", 서버 로그에 원본 HTML 스냅샷 저장 (디버깅용)
- 안티봇/캡차 감지: 재시도하지 않고 즉시 에러 반환 (계정 잠김 방지), "잠시 후 다시 시도해주세요" 안내
- 세션 만료(캐시 쿠키 TTL 초과): 자동 재로그인 1회 후 재시도, 재시도도 실패하면 `502`

## 테스트

- 크롤러 파서: 저장된 HTML/JSON 픽스처 기반 유닛 테스트 (실제 사이트 호출 없음, 사이트 구조 변경 시 픽스처만 갱신)
- API 라우트: FastAPI `TestClient`로 계약 테스트 (`KoreanAirClient`는 목 처리)
- 프론트: 화면 흐름 수동 QA. 실제 대한항공 대상 자동 e2e는 지양 (계정 잠김 위험)

## 비범위 (Out of scope)

- 실제 예약/결제
- 편도 조회
- 다중 사용자/앱 자체 로그인
- 좌석 데이터 백그라운드 캐싱 (항상 실시간 조회)

## 리스크 / 구현 착수 시 먼저 확인할 것

- **비로그인 조회 가능 여부 미확인**: 대한항공 마일리지 좌석 조회가 비로그인 상태에서도 노출되는지 실사로 확인 안 됨 (사용자도 항상 로그인해서만 조회해봤다고 함). `KoreanAirClient` 구현 착수 전 실제 브라우저로 먼저 확인하고, 비로그인으로 가능하면 로그인 로직 자체를 스킵하는 쪽으로 단순화. 안 되면 현재 설계(로그인 후 조회) 그대로 진행
- **anti-bot/캡차 대응**: 로그인 자동화 시 대한항공 측 봇 탐지로 계정 잠김 위험 있음. 구현 시 요청 빈도 제한, 실패 시 즉시 중단(재시도 금지) 원칙 지킬 것
- **kds-switch 등 커스텀 웹컴포넌트**: 사이트가 Angular 기반 커스텀 엘리먼트(shadow DOM) 다수 사용 확인됨. Playwright locator가 shadow DOM 관통 못 할 수 있어 `page.locator` 대신 실제 좌표 클릭이나 accessibility selector 필요할 수 있음
